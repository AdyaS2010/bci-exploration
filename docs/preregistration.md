## 1. Question and hypotheses

**Question.** With real-time feedback, can I learn to voluntarily increase upper-alpha (10–12 Hz) power at the Muse's temporal sites, beyond what happens with an identical-looking sham feedback?

"Learning" is measured two ways, and both are primary:

- **H1, within-session learning.** Within a session, target power rises across the six training blocks (relative to that session's resting baseline) more steeply in real-feedback sessions than in sham sessions.
- **H2, between-session learning.** Across sessions, the session-average training level (relative to baseline) rises more steeply over the real-feedback sessions than over the sham sessions.

Both hypotheses are directional (real > sham), so the tests are one-sided.

**Specificity (secondary).** If the real-feedback effect exists, it should be (S1) specific to the upper-alpha band rather than broadband, and (S2) not explained by muscle, eye, or contact artifacts. §6 defines these checks.

## 2. Design

**Single-subject, randomized, blinded, sham-controlled crossover.** 20 training sessions: 10 real, 10 sham.

- **Schedule.** Sessions are assigned in 5 blocks of 4. Each block contains 2 real and 2 sham sessions in random order. Blocking keeps conditions balanced over time, so a general trend (getting used to the headset, the semester getting busier) can't line up with one condition.
- **Blinding (participant).** The schedule is generated by script from a random seed before session 1 and saved to `data/` (git-ignored). Its SHA-256 hash is committed in the deviations log before session 1, which proves the schedule wasn't changed later. The session script reads the condition from the schedule and never displays it. I stay blind until all 20 sessions are complete.
- **Blinding limits, stated honestly.** I'm also the experimenter, so this is single-blind at best. A careful participant might learn to tell real from sham by testing whether the bar responds to deliberate strategies. The blinding check (§6.5) measures whether that happened.
- **Sham type.** Yoked sham. A sham session replays the displayed feedback trace from the most recent completed real session, so it has realistic dynamics. If no real session has happened yet, sham uses the randomized smooth random walk in `ShamFeedback`. In both modes the artifact freeze is identical: a blink freezes the bar whether the session is real or sham.
- **Schedule and dose.** 3 sessions per week at a similar time of day (±2 h), about 7 weeks. No more than one session per day.

**Why this design over an alternative.** A "sham phase, then real phase" design avoids carryover but confounds condition with time. With randomized blocks, time is balanced. The cost is that learning in real sessions can carry over into sham sessions. That biases H2 toward a null, which makes the test conservative, not flattering. §9 discusses this.

## 3. Target signal and montage

All values come from `src/kestrel/config.py` at the freeze commit.

| Setting | Value | Why |
|---|---|---|
| Target band | **Upper alpha, 10–12 Hz** (`UPPER_ALPHA`) | Upper alpha is the sub-band used in the best-known alpha-training studies (Hanslmayr et al., 2005; Zoefel et al., 2011). Those studies set the band from each person's alpha peak. Here it's fixed at 10–12 Hz before any data, so it can't be tuned after seeing results. My peak frequency is reported as exploratory. |
| Target channels | **TP9 and TP10**, averaged (`NF_CHANNELS`) | Closest Muse sites to the posterior alpha generators, and further from the eyes than AF7/AF8. |
| Target measure | log10 absolute band power (µV²), Welch PSD, 1 s Hann segments, 50% overlap | Log makes the skewed power distribution roughly symmetric. |
| Live window | 2 s, updated every 0.25 s (`NF_WINDOW_SECONDS`, `NF_UPDATE_SECONDS`) | Matches the 2 s offline epochs, so live and offline values are comparable. |
| Live filtering | Causal 60 Hz notch + 1–40 Hz 4th-order Butterworth bandpass (`clean_causal`) | Causal, so the newest samples aren't distorted. Tested to match offline power within 2%. |
| Feedback mapping | z-score against this session's 2-min pre-baseline, then logistic → 0–1 bar (`feedback_from_power`) | 0.5 means "typical for me today", which absorbs day-to-day contact differences. |
| Artifact freeze | Any channel over **150 µV peak-to-peak** in the window → bar frozen, window flagged (`REJECT_PEAK_TO_PEAK_UV`) | Doesn't reward blinks or clenches. Applied identically in real and sham. |
| Display | Terminal bar, no sound. Eyes open, looking at the bar. | Keeps the eyes open and gaze fixed, which matters because eye closure alone raises alpha. |

## 4. Session protocol

Each session is about 30 minutes, run by one script. Every block is saved as a raw recording with a JSON sidecar.

1. **Setup and contact check (60 s, eyes open, no feedback).** Proceed only if every channel has ≤30% of epochs over the artifact threshold (the `record_session.py` summary). Otherwise refit, up to 3 tries. If it still fails, don't run the session (see §8).
2. **Catch blocks, every session.** 20 s blinking every ~2 s (`blink`), then 20 s of jaw clenches every ~2 s (`clench`). These measure that day's artifact signatures and whether the threshold catches them.
3. **Pre-baseline (120 s, eyes open, relaxed, no feedback).** Sets the z-score for feedback and the reference for all outcomes.
4. **Training: 6 blocks × 180 s with feedback, 30 s rest between blocks.** Instruction, identical every session: *"Try to make the bar go up. Keep your eyes open and on the screen, and keep your face and jaw relaxed."* No strategy is prescribed. I note the strategies I use afterwards.
5. **Post-baseline (120 s, eyes open, no feedback).**
6. **Questionnaire:** (a) real or sham? plus confidence 1–5; (b) sleepiness on the Karolinska Sleepiness Scale (1–9); (c) strategies used, in free text; (d) hours of sleep last night; (e) caffeine in the last 3 h (y/n).

## 5. Primary outcome: EEG learning

All outcomes are computed **offline from the saved raw recordings** with the standard pipeline (`recording_features`: 60 Hz notch, 1–40 Hz zero-phase bandpass, 2 s epochs with 50% overlap, 150 µV rejection). They are not taken from the live feedback log. That way the outcome doesn't depend on the live display code.

**Block measure.** For each training block *b* in session *s*:

> Δ(s, b) = mean over clean epochs of log10 upper-alpha power (TP9, TP10 averaged), minus the same quantity for session *s*'s pre-baseline.

Δ is a log ratio to baseline: Δ = 0.1 means about 26% more power than baseline.

**P1, within-session learning (tests H1).**
- For each session, slope of Δ(s, b) over blocks b = 1…6 (`linear_trend`). One slope per session.
- Compare the 10 real-session slopes against the 10 sham-session slopes with Welch's t-test, one-sided (real > sham), and Cohen's d with 95% CI (`compare_two`).

**P2, between-session learning (tests H2).**
- For each session, the training level L(s) = mean of Δ(s, b) over its 6 blocks.
- Fit the slope of L over the real sessions' order (1…10), and separately over the sham sessions' order (1…10) (`linear_trend`).
- Test statistic: the difference in slopes (real − sham), with standard error √(SE_real² + SE_sham²) and a one-sided test of whether the difference is greater than 0.

**Multiple testing.** P1 and P2 are two co-primary tests, corrected with Holm's method at family-wise α = .05 (one-sided): the smaller p is tested at .025, the other at .05.

**The unit of analysis is the session.** Epochs within a session are overlapping and autocorrelated, so no primary test treats epochs as independent. Building the pipeline showed why this matters: two recordings of the same synthetic signal gave an epoch-level d of −1.58 on one channel.

**Reporting.** Effect sizes and their 95% CIs come first, and p-values second. Every session's data is plotted: block-by-block Δ for all 20 sessions, colored by condition, plus L(s) over time.

### Power, honestly

With 10 sessions per condition and the first Holm step at one-sided α = .025, this design has 80% power only for **very large effects (d ≥ 1.32)**. For a large effect (d = 0.8) power is about 39%. For a medium effect (d = 0.5) it's about 18%. This is a pilot. A null result here rules out only very large effects, and §9 says so explicitly. Extending to 24 sessions (12 per condition) lowers the 80%-power threshold only to d ≈ 1.2, so the realistic path to detecting smaller effects is replication, not a longer run.

## 6. Secondary outcomes: specificity and controls

All are computed with the same pipeline and the same session-level approach as P1. They are reported whatever the primary result.

### 6.1 Band specificity (S1)

Repeat P1 exactly, swapping upper alpha for each of:

- lower alpha, 8–10 Hz
- theta, 4–8 Hz
- beta, 13–30 Hz
- *relative* upper alpha (10–12 Hz power / 1–40 Hz power)

**Specificity is supported** if the real-vs-sham d for upper alpha is larger than the d for each of the three neighboring bands, and if relative upper alpha shows the same direction of effect. If absolute upper alpha rises but relative upper alpha doesn't, the change is broadband (contact, arousal, or muscle), not a trained alpha change.

### 6.2 Artifact controls (S2)

The effect is treated as **possibly artifact-driven** if any of these hold:

- **Rejection rate.** The fraction of rejected training epochs differs between real and sham sessions (session-level Welch test, |d| > 0.5), or rises across blocks in real sessions only.
- **Muscle (EMG).** Gamma power (30–40 Hz) at TP9/TP10 shows a real-vs-sham within-session slope effect in the same direction as upper alpha, with d > 0.5. Also reported: the within-session correlation between block Δ in upper alpha and block Δ in gamma.
- **Eyes.** Eye closure and gaze defocus both raise alpha. Two checks: blink counts per block, from AF7/AF8 deflections over 100 µV, compared real vs sham; and any block containing 10 s or more with no blink is flagged as possible eye closure and reported. The primary analysis includes all blocks, and a sensitivity analysis re-runs P1 without flagged blocks.

### 6.3 Catch blocks

For every session, report the fraction of blink and clench epochs rejected by the 150 µV threshold, and how much a clench raises 10–12 Hz power at TP9/TP10 compared with the pre-baseline. That second number measures how much muscle activity can masquerade as upper alpha. If the threshold catches fewer than 80% of deliberate blink or clench epochs in the pre-study catch recordings (§10), the threshold is lowered before session 1. The change is logged in §12 and then frozen.

### 6.4 Manipulation check (CRED-nf)

- **Did the target move?** In real sessions, report mean Δ across training blocks with a 95% CI (one value per session). This is the plain question of whether the trained signal changed at all during feedback.
- **Was the sham really decoupled?** From the live logs, the correlation between the displayed value and the true live value should be ≈ 1 in real sessions and ≈ 0 in sham sessions. A sham session with |r| > 0.3 is reported as a failed sham.
- **Did live match offline?** The correlation between live-logged target power and offline-computed power per block is reported as a pipeline integrity check.

### 6.5 Blinding check

Report the proportion of sessions where my real-or-sham guess was correct, with a binomial test against 50% and a confidence-weighted breakdown. If accuracy is 75% or higher (15/20 or more), blinding is considered broken, and any positive primary result is reported as potentially expectation-driven.

### 6.6 Exploratory (no hypotheses)

- Post-baseline minus pre-baseline upper alpha (does training change resting alpha afterwards?)
- Frontal alpha asymmetry across sessions
- Sleepiness, sleep hours, and caffeine as covariates
- Strategies from the free-text notes, linked to high- and low-Δ blocks

These are labeled exploratory wherever they're reported.

## 7. Data handling

- Raw recordings and live logs stay local in `data/` (git-ignored) and are never committed. The subject ID is pseudonymous (S01).
- Analysis code is committed before it's run on real data. Output figures and summary tables (no raw EEG) go in `docs/`.
- The schedule file and its hash are handled as described in §2.

## 8. Exclusions and stopping

**A session is not run** (rescheduled, keeping the same condition assignment) if I slept under 5 hours, am ill, or fail the contact check after 3 refits.

**A completed session is excluded from the primary analysis** if any of these hold:

- more than 40% of training epochs are rejected
- more than 10% of expected samples are missing (Bluetooth loss, from the sidecar counts)
- the pre-baseline has fewer than 30 clean epochs, so the reference is unreliable

Excluded sessions are rerun with the same condition in the next free slot, until each condition has 10 included sessions or 26 sessions have been attempted, whichever comes first. Every exclusion goes in §12. There is **no peeking**: no real-vs-sham comparison is computed before session 20. The only thing I see during the study is the bar.

## 9. What a null result looks like, and why it still matters

"Null" is defined in advance, so it can't be reinterpreted after the fact.

| Outcome pattern | What it means |
|---|---|
| **A. Neither condition changes.** P1 and P2 CIs include 0, and real-session Δ ≈ 0. | Under these parameters (Muse temporal sites, 10–12 Hz, 20 sessions), I didn't learn to move upper alpha. Many people in neurofeedback studies are "non-learners", and consumer electrodes far from the alpha generators may not register what changes. |
| **B. Both conditions rise equally.** Δ > 0 in both, P1/P2 ≈ 0. | Something raised alpha, but not the feedback: relaxation, practice, time of day, or expectation. This is exactly the effect an uncontrolled app would credit to "training". |
| **C. Real > sham, but not specific.** Neighboring bands move as much, or relative upper alpha doesn't. | Feedback changed something broad (arousal, contact, muscle tone), not upper alpha specifically. |
| **D. Real > sham, but it tracks artifacts.** Gamma, rejection rate, or blink changes follow the effect. | I learned to move muscles or eyes, not brain rhythms. That's a real finding about how easily consumer neurofeedback can be fooled. |
| **E. Blinding broke.** 75% or more correct guesses. | Real and sham can't be cleanly separated. Any difference may be expectation. |

**Why a null still matters:**

1. **It bounds the effect.** With the CIs in §5, a null says effects larger than a stated size are unlikely for this setup. That's a quantitative statement, not a shrug. The power analysis makes clear only very large effects are ruled out.
2. **It's the honest answer to the question the Muse app never asks.** The app shows "calm" going up. Patterns B and D show how that can happen without any learned brain control. Demonstrating that with a controlled design is the contribution.
3. **It tests the method.** A pipeline that can report a clean null (validity gate passed, artifacts measured, sham verified, blinding checked) is the reusable part, whatever the result.
4. **CRED-nf asks for it.** Unpublished nulls bias the neurofeedback literature toward positive results. Reporting this one completely is part of doing it right.
5. **It shapes Semester 2.** Pattern A points toward changing the target (individual alpha frequency, different sites or hardware). B points toward stronger controls. D points toward better artifact handling (for example, adding ICA via MNE).

A positive result gets the same scrutiny: it only counts as support for learned upper-alpha control if P1 or P2 passes **and** the S1 and S2 checks pass **and** blinding held.

## 11. Known limitations

- **Single subject,** who is also the experimenter. Results describe one person and don't generalize.
- **Four dry electrodes,** no occipital coverage. TP9/TP10 alpha is a distant, mixed view of posterior alpha.
- **Consumer hardware:** variable contact, Bluetooth dropouts, and no impedance measurement. The contact check and sample-loss exclusions only partly compensate.
- **Carryover** in the crossover design biases H2 toward the null.
- **Low power** for anything but very large effects (§5).
- **Amplitude thresholding is the main artifact defense.** Low-amplitude muscle activity below 150 µV can still add broadband power, which is why S1's relative-power check and S2's gamma check exist.
